RazeHack Lua API

Create subtabs, groups and controls inside the RazeHack menu with Lua. Scripts get the same look and feel as native options.

⬇ Download RazeHack at www.unknowncheats.me

Native look

Controls use the menu style: checkboxes with a key, color or gear panel, sized buttons and more.

Integrated

New subtabs sit next to the built-in ones and their controls appear in the menu search.

Extendable

Add controls to existing groups, or build floating windows.

Loading a script

  • Save your .lua file in the scripts folder. Subfolders are supported.
  • Open the Lua Script tab, press Refresh, select the script and press Load.
  • Output from print() and any errors appear in the Console pane.
  • When a script is unloaded, every control it created is removed.

Your first script

A new subtab inside the Exploits tab, with a group and a checkbox.

local tab = gui.Tab(gui.Reference("Exploits"), "hello.tab", "Hello")
local box = gui.Groupbox(tab, "My group", 10, 10)
local chk = gui.Checkbox(box, "hello.chk", "Enable", true)

print("Checkbox is:", chk:GetValue())

A group with x below 160 goes to the left column. A group with x of 160 or more goes to the right.

local tab   = gui.Tab(gui.Reference("Exploits"), "hello.tab", "Hello")
local left  = gui.Groupbox(tab, "Left", 10, 10)
local right = gui.Groupbox(tab, "Right", 345, 10)

gui.Checkbox(left,  "hello.a", "Option A", true)
gui.Checkbox(right, "hello.b", "Option B", false)
local tab = gui.Tab(gui.Reference("Exploits"), "hello.tab", "Hello")
local box = gui.Groupbox(tab, "Actions", 10, 10)

local speed = gui.Slider(box, "hello.speed", "Speed", 50, 0, 100)

gui.Button(box, "Print value", function()
    print("Speed:", speed:GetValue())

Native groups

Add controls to a group that already exists in the menu.

gui.Reference("Tab", "Subtab", "Group")
  • Tab, subtab and group names must match the menu. They are not case sensitive.
  • Controls are drawn at the end of that group.
  • If the group does not exist on that page, the controls appear in a new box at the end of the page.
  • You do not need gui.Tab or gui.Groupbox: the returned object is already the group.
-- Tab Exploits, subtab Exploits_, group Movement
local ref   = gui.Reference("Exploits", "Exploits_", "Movement")
local walls = gui.Checkbox(ref, "show.walls", "Show Walls", false)
local ref   = gui.Reference("Exploits", "Exploits_", "Movement")
local walls = gui.Checkbox(ref, "show.walls", "Show Walls", false)

local last = nil
local function update()
    local on = walls:GetValue()
    if on == last then return end
    last = on
    client.SetConVar("r_drawclipbrushes", on and 2 or 0, true)
end

callbacks.Register("Draw", "show_walls", update)
local ref = gui.Reference("Aims", "Aimbot", "General")

gui.Checkbox(ref, "my.smooth.on",  "Extra smoothing", false)
gui.Slider(ref,   "my.smooth.val", "Amount", 5, 1, 20)
gui.Button(ref,   "Test", function() print("testing") end)
This does not create subtabs. To add your own subtab use gui.Tab and gui.Groupbox. Both approaches can be used together.

gui.Groupbox

Creates a titled box that holds controls inside a subtab.

gui.Groupbox(parent, name [, x, y, width, height]) → GuiObject
ParameterBehavior
xPicks the column. Below 160 is left, 160 or more is right.
yVertical order inside the column. Lower values go first.
widthNarrows the group. It never exceeds half the page.
height0 fits the content automatically. A value fixes the height with a minimum of 90 px.
Tip. Leave the height at 0. The group grows as you add controls. With a fixed height, extra controls are cut off.
local tab = gui.Tab(gui.Reference("Exploits"), "demo.tab", "Demo")

local box1 = gui.Groupbox(tab, "Main", 10, 10)
local box2 = gui.Groupbox(tab, "Timing", 345, 10)

Three groups in the left column, ordered by y.

local tab = gui.Tab(gui.Reference("Exploits"), "demo.tab", "Demo")

local a = gui.Groupbox(tab, "First",  10, 10)
local b = gui.Groupbox(tab, "Second", 10, 20)
local c = gui.Groupbox(tab, "Third",  10, 30)

Size values are accepted. Here a height of 50 is raised to 90 and the group stops auto-growing.

local g1 = gui.Groupbox(tab, "Group A", 16, 16, 287.5, 50)
local g2 = gui.Groupbox(tab, "Group B", 319.5, 16, 287.5, 100)

gui.Window

Creates a floating window, independent from the menu, with the same border and style.

gui.Window(varname, name, x, y, width, height) → GuiObject
  • SetActive(true/false) shows or hides the window. IsActive() tells whether it is visible.
  • SetOpenKey(key) toggles it with a key, even when the menu is closed.
  • Without an open key it is only visible while the menu is open.
  • With an open key, the window stays visible when the menu is closed. It is read-only until you open the menu again.
  • Window controls are not included in menu search.
local wnd = gui.Window("demo.wnd", "My window", 100, 100, 260, 300)

gui.Checkbox(wnd, "demo.wnd.chk", "Checkbox", true)
gui.Slider(wnd, "demo.wnd.sld", "Slider", 50, 0, 100)
local wnd = gui.Window("demo.wnd", "Quick panel", 100, 100, 260, 220)
gui.Checkbox(wnd, "demo.wnd.chk", "Quick option", false)

wnd:SetOpenKey("F6")   -- toggles with F6
local wnd = gui.Window("demo.wnd", "My window", 100, 100, 260, 220)
gui.Text(wnd, "Hello from Lua")

gui.Button(wnd, "Close", function()
    wnd:SetActive(false)
end)

A window with an open key stays on screen after the main menu is closed. It becomes read-only until the menu is opened again.

gui.GetValue

Reads a value by path. It first looks at controls created by Lua, where the path is the varname. If none matches, it looks at the menu variables that RazeHack exposes. Colors are returned as a table { r, g, b, a }.

gui.GetValue(path) → any

local fov     = gui.GetValue("aims.aimbot.fov")
local c = gui.GetValue("aims.aimbot.fovcolor")
print(c[1], c[2], c[3], c[4])
Finding paths. Every menu variable you can read or write is listed in lua_variables.txt, inside the RazeHack folder. See Menu variables. You can also list them from Lua with gui.NativePaths().

GuiObject

Every control, group, subtab and window is a GuiObject. These methods are available on all of them.

MethodDescription
GetName()Returns the visible name.
SetName(text)Changes the visible name.
GetValue()Returns the current value (boolean, number, index or text depending on the control).
SetValue(value)Sets the value. SetValue("varname", value) sets a child by its varname.
GetString()Returns the value as text.
SetString(text)Sets the value from text.
SetText(text)Changes the text of a Text or Button. On an Editbox it changes the content.
SetDescription(text)Adds a description under the control.
SetActive(bool)Shows or hides the object. On a window, opens or closes it.
IsActive()Returns whether it is visible.
SetInvisible(bool)Hides or shows the object.
SetDisabled(bool)Disables it: visible but not usable.
SetOptions(...)Replaces the options of a Combobox or Listbox.
SetOpenKey(key)Key that toggles a window.
SetPosX(n), SetPosY(n)On a groupbox: column and order. On a window: position.
SetWidth(n), SetHeight(n)Size of a groupbox, button, listbox, editbox or window.
Remove()Removes the object.
Reference(...)Finds a child by name.
Children()Iterator over child objects.
SetIcon(texture, scale)Reserved. It currently does nothing.

Additional methods

MethodDescription
SetColor(r, g, b [, a])Sets the color of a Button or Text, or the picker of a CheckboxColor.
GetColor()Returns r, g, b, a.
SetKey(key)Sets the key of a CheckboxBinder or Keybox.
GetKey()Returns the key code.
local chk = gui.Checkbox(box, "my.chk", "Option", true)

chk:SetDescription("Enables the main feature")
chk:SetDisabled(true)     -- visible but not usable

local main  = gui.Checkbox(box, "my.main", "Show extra", false)

callbacks.Register("Draw", "toggle_extra", function()
    extra:SetInvisible(not main:GetValue())
end)
local function print_children(obj, prefix)
    print(prefix .. obj:GetName())
    for child in obj:Children() do
        print_children(child, prefix .. "    ")
    end
end

print_children(box, "")
local temp = gui.Checkbox(box, "my.temp", "Temporary", true)

    temp:Remove()

PreMove / PostMove

CreateMove has two extra stages around it, in the same order the engine runs them.

EventRunsTypical use
PreMoveBefore the client predicts the command.Movement changes that should be seen by prediction: strafe, bunnyhop.
CreateMoveThe normal point, same as before.Aimbot, triggerbot, anti-aim, general logic.
PostMoveAfter the command was predicted.Corrections that must see the final predicted state, such as a silent aim fix.

All three receive the same UserCmd object.

callbacks.Register("PreMove", "stage_pre", function(cmd)
    -- runs before prediction
end)

callbacks.Register("CreateMove", "stage_move", function(cmd)
    -- normal point, same as a regular CreateMove hook
end)

callbacks.Register("PostMove", "stage_post", function(cmd)
    -- runs after prediction
end)

cmd.sendpacket controls whether this command is actually sent to the server. Works in any of the three stages.

callbacks.Register("CreateMove", "skip_packet", function(cmd)
    if input.IsButtonDown("X") then
        cmd.sendpacket = false
    end
end)
If a script only reads data or changes buttons, the stage does not matter. Use PreMove/PostMove only when prediction order actually matters for what the script does.

RenderView / PostScreenSpaceEffects

Two points tied to rendering the 3D view, both give a ViewSetup.

callbacks.Register("RenderView", [name,] function(view) ... end)

RenderView runs once per rendered view (including the HUD's own view) and once more after post screen-space effects are applied, so a script can see the same kind of data from either point without needing a separate event.

Read-only in practice. By the time Lua sees the view here, the frame is already set up. Changing fields rarely has a visible effect; use it to read data, not to change the camera.

DispatchUserMessage

Runs for every user message the server sends (screen shake, screen fade, hint text, and so on). Return false to block the message, or true (or nothing) to let it through.

callbacks.Register("DispatchUserMessage", [name,] function(msgType) ... end) → boolean

If several scripts register this event and any one of them returns false, the message is blocked.

local BLOCK_TYPE = 10   -- replace with the real message type for your build

callbacks.Register("DispatchUserMessage", "block_shake", function(msgType)
    if msgType == BLOCK_TYPE then
        return false
    end
    return true
end)
callbacks.Register("DispatchUserMessage", "log_msgs", function(msgType)
    print("User message:", msgType)
    return true
end)
Message type numbers. These depend on your build's message table. Print msgType first to find the number you want to match.

CLMove / SendMove

Low level notifications tied to the client's movement and network send cycle.

callbacks.Register("CLMove", [name,] function(extraSamples, final) ... end) → number callbacks.Register("SendMove", [name,] function() ... end)
EventParametersRuns
CLMoveextraSamples (number), final (boolean)Once per client movement cycle. final is true on the last sub-tick of the frame.
SendMovenoneRight after a command packet is sent to the server.

A CLMove callback can optionally return a number: how many extra movement passes to run that tick, up to 14. If several scripts return a value, the highest one is used. Returning nothing or 0 runs the tick normally.

callbacks.Register("CLMove", "watch_move", function(extraSamples, final)
    if final then
        print("Final sub-tick, extra samples:", extraSamples)
    end
end)

callbacks.Register("SendMove", "count_sends", function()
    -- a packet was just sent
end)

A CLMove callback can return a number of extra movement passes to run that tick. Returning 0 or nothing runs the tick normally.

local tab = gui.Tab(gui.Reference("Exploits"), "speedhack.tab", "SpeedHack")
local box = gui.Groupbox(tab, "SpeedHack", 10, 10)

bytepatch

Overwrite bytes in the game's code at runtime, and restore them later. This is how the menu's own code patches work, exposed to scripts for the same kind of use.

  • Find the address to patch with mem.FindPattern or mem.GetModuleBase, not a fixed number. A pattern survives game updates; a fixed address usually does not.
  • Every patch a script applies is tracked and undone automatically when the script is unloaded, even if the script never calls Restore itself.
  • Patches are limited to 64 bytes per call.
bytepatch.PatchFill bytes with a single value bytepatch.PatchBytesWrite a specific sequence of bytes bytepatch.RestoreUndo a patch Example: ChargerTurnToggle a patch from a checkbox
This can crash the game. A wrong address, a wrong size, or patching the wrong bytes can crash instantly or cause corrupted behavior. There is no safety check beyond the size limit. Test changes carefully, and always have a working way to undo a patch.

bytepatch.Restore

Restores the original bytes at an address. Returns true if a patch was found and restored at that exact address and size.

bytepatch.Restore(address, count) → boolean
bytepatch.Restore(addr, 1)
local addr = mem.FindPattern("client.dll", "74 ? D9 86 ? ? ? ? 8D 47")

gui.Button(box, "Apply patch", function()
    if addr then bytepatch.Patch(addr, 0xEB, 1) end
end)

gui.Button(box, "Undo patch", function()
    if addr then bytepatch.Restore(addr, 1) end
end)
Unloading the script restores every patch it applied, even without calling this. Call it directly only when a script needs to undo a patch while it is still running, for example when a checkbox is turned off.

Example: ChargerTurn

A checkbox that applies a one-byte patch when turned on, and restores it when turned off. The pattern is scanned once, and the patch is only re-applied when the checkbox actually changes.

local tab = gui.Tab(gui.Reference("Exploits"), "chargerturn.tab", "ChargerTurn")
local box = gui.Groupbox(tab, "ChargerTurn", 10, 10)

local enable = gui.Checkbox(box, "lua_chargerturn", "Enable", false)
local addr = mem.FindPattern("client.dll", "74 ? D9 86 ? ? ? ? 8D 47")

if not addr then
    print("ChargerTurn pattern not found")
end

local last = nil

local function apply(on)
    if not addr then return end

    if on then
        bytepatch.Patch(addr, 0xEB, 1)
    else
        bytepatch.Restore(addr, 1)
    end
end

callbacks.Register("FrameStageNotify", "chargerturn_patch", function(stage)
    if stage ~= FRAME_RENDER_START then return end

    local value = enable:GetValue()
    if value == last then return end

    last = value
    apply(value)
end)
Lua libraries

ffi

RazeHack runs on LuaJIT, so scripts have access to LuaJIT's built-in ffi library. It lets a script read and write raw memory using C-style types, which is how advanced scripts reach data that is not exposed through mem, entity properties, or any other library.

  • ffi is a standard part of LuaJIT, not something RazeHack adds. Its full documentation is at luajit.org/ext_ffi.html.
  • Addresses from mem (mem.GetModuleBase, mem.FindPattern) are plain numbers. Cast them to a pointer with ffi.cast before reading or writing through them.
  • A wrong type, a wrong offset, or an invalid address can crash the game instantly. There is no safety net here, unlike entity properties, which are bounds-checked by the engine.

When to use ffi instead of other libraries. If what you need already exists as a entity property, a menu variable, or a function in engine/client, use that instead — it is safer and does not depend on offsets that can change between game updates. Reach for ffi only for data that genuinely has no other way to reach it from Lua.
ffi

Reading memory

The basic pattern: cast a number address to a typed pointer, then dereference it.

local addr = 0x10020000  -- example address, a number
local ptr = ffi.cast("int*", addr)
print(ptr[0])             -- reads a 4-byte int at that address
local ptr = ffi.cast("float*", addr)
print(ptr[0])
ffi.cast("bool*", addr)[0]
ffi.cast("uint8_t*", addr)[0]
ffi.cast("int32_t*", addr)[0]
ffi.cast("float*", addr)[0]
ffi.cast("double*", addr)[0]
ffi.cast("void**", addr)[0]     -- reads a pointer stored at addr

Reading a pointer, then reading a value at an offset from it — the Lua equivalent of *(int*)(*(void**)base + 0x10).

local base = mem.GetModuleBase("client.dll")

local first = ffi.cast("void**", base + 0x427698)[0]
if first ~= nil then
    local value = ffi.cast("int*", ffi.cast("intptr_t", first) + 0x10)[0]
    print(value)
end
ffi

Writing memory

Writing uses the same cast, then an assignment instead of a read.

local addr = 0x10020000
ffi.cast("int*", addr)[0] = -1
ffi.cast("bool*", addr)[0] = true

The raw memory equivalent of what clientstate already exposes safely. Shown here only as an ffi example; prefer the clientstate library for this in real scripts.

-- void* Network_Channel = *(void**)(*(uint32*)(engine_base + 4352236) + 24)
local engine_base = mem.GetModuleBase("engine.dll")
local client_state = ffi.cast("uint32_t*", engine_base + 4352236)[0]
local net_channel = ffi.cast("void**", client_state + 24)[0]

if net_channel ~= nil then
    local nc = ffi.cast("intptr_t", net_channel)
    ffi.cast("int32_t*", nc + 16)[0] = -1
    ffi.cast("int32_t*", nc + 28)[0] = 255
end
No bounds checking. Writing to the wrong offset writes into unrelated memory. There is no error, no warning — just undefined behavior or a crash.
ffi

Typed structs

ffi.cdef defines a C layout once. After that, casting an address to the struct type gives named field access instead of manual offsets.

ffi.cdef[[
    typedef struct {
        int32_t  m_nOutSequenceNr;    // +0
        int32_t  m_nInSequenceNr;     // +4
        int32_t  m_nOutSequenceNrAck; // +8
    } NetChannelLite;
]]

local addr = net_channel_address  -- a number
local nc = ffi.cast("NetChannelLite*", addr)

print(nc.m_nOutSequenceNr)
nc.m_nOutSequenceNr = nc.m_nOutSequenceNr + 1
ffi.cdef[[
    typedef struct {
        float x, y, z;
    } Vec3Raw;
]]

local pos = ffi.cast("Vec3Raw*", entity_addr + 0x3C)
print(pos.x, pos.y, pos.z)
Only define each ffi.cdef struct once per script run. Calling it twice with the same name errors; wrap it in a check if the script can reload the same definition.
ffi

Combined with mem

The usual flow: find an address with mem, then read or write through it with ffi.

local addr = mem.FindPattern("client.dll", "74 ? D9 86 ? ? ? ? 8D 47")

if addr then
    local value = ffi.cast("float*", addr + 4)[0]
    print("Value at pattern + 4:", value)
end
ffi.cdef[[
    typedef struct {
        int32_t  m_nSignonState;
    } ClientStateLite;
]]

local engine_base = mem.GetModuleBase("engine.dll")
if engine_base then
    local cs = ffi.cast("ClientStateLite*", engine_base + 0x1000)  -- example offset
    print(cs.m_nSignonState)
end
For anything already covered by clientstate, entity properties, or the rest of the API, prefer those over raw ffi reads — they keep working even if internal offsets shift between game updates.

Troubleshooting

My subtab does not appear

  • Make sure the script is loaded and the Console shows no errors.
  • The name in gui.Reference("...") must be one of the menu tabs. Unknown names go to Lua Script.
  • Check capitalization of your variables. Tab and tab are different in Lua.

My checkbox in a native group is missing

  • Tab, subtab and group must match the menu. If the group does not exist, the controls show in a new box at the end of the page.
  • gui.Reference("Exploits") alone only returns the tab. A group needs all three names.

My function never runs

A function that is only defined does nothing. Register it with callbacks.Register.

local function full_bright()
    -- never called
end
local function full_bright()
    -- called every frame
end

callbacks.Register("Draw", "full_bright", full_bright)

A group is cut off or does not grow

A fixed height in gui.Groupbox turns off auto sizing. Leave the height at 0.

Window controls are not found in search

This is intended. Only controls in subtabs and native groups are indexed.

Names containing ##

The menu appends an internal id to each label. Avoid ## in your own names.
